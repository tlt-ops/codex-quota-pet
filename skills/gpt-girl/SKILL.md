# GPT 娘额度桌宠

Bounce mode resolves contact within each animation frame and keeps at least an 18-degree departure angle from the contacted edge. Random rebound direction and speed loss remain enabled. The fifth rebound starts a 1.1-second fade; a fading sticker keeps moving through any subsequent edge instead of clamping to it, with no sixth rebound. Motion is implemented in `native/macos/app/BounceMotion.swift` and covered by `native/macos/tests/BounceMotionHarness.swift`. Stickers use `native/macos/app/ParticlePanel.swift` to disable AppKit's menu-bar frame constraint, so their actual window position follows the full-screen motion bounds. If sprites appear to stick, compare their actual panel and WindowServer positions against the requested positions; math-only trajectory tests cannot detect AppKit moving a window to a different location. `native/macos/tests/ParticlePanelHarness.swift` tests actual edge placement; its optional `--live` run also samples visible motion through five rebounds and fading.

The macOS edition is a local native companion app. The app uses a separate LaunchAgent watcher so that opening the Codex desktop app opens the pet. The companion obtains quota data through the installed `codex app-server` `account/rateLimits/read` method. It does not inspect prompts, transcripts, files, or browser pages.

This repository contains a native macOS implementation in `native/macos/` and a separate Windows Electron port at the repository root. When working on macOS, inspect `native/macos/scripts/` and the installed LaunchAgent state. Run the read-only `native/macos/scripts/quota_client.py` to refresh quota if needed. For Windows, follow `docs/windows.md` and use the root package scripts. Report the actual remaining percentage and reset time from its output, including the limit window shown by the server; do not assume a five-hour window exists.

The app monitors fresh quota snapshots for sound events in the displayed limit window. Each whole percentage point of displayed quota lost queues one Minecraft hurt sound. A displayed reset deadline, confirmed quota recharge (including an official free reset), or increase in the available reset count queues one XP orb sound; coincident events in one snapshot are combined. The first fresh snapshot after launch or a quota-read failure is a silent baseline, so historical changes are not replayed. On launch, the app downloads the official clips from Minecraft's resource CDN using hashes in Mojang's [asset index](https://piston-meta.mojang.com/v1/packages/32a06dd28a0a8a981f4a1dffbdb3931f3075ca6c/34.json), verifies their SHA-1, and caches them under `~/Library/Application Support/CodexQuotaPet/Sounds/`. If a first-launch download fails, quota display continues without sounds and download is retried at the next launch. The distributable App and plugin archives do not contain Minecraft audio; see the [Minecraft Usage Guidelines](https://www.minecraft.net/en-us/usage-guidelines). When troubleshooting silent alerts, check the local sound cache, network access at first launch, and whether two fresh quota snapshots have established a real change before claiming playback has failed.

Exactly two consecutive clicks on the character open a radial wheel over GPT 娘 at the click position, adjusted to fit on screen near an edge. Three or more rapid clicks each launch a projectile and do not open the wheel. Right-clicking the character opens the same wheel as a fallback, and the status-bar menu can also open it. Clicking the quota bubble opens its separate menu. The wheel includes Show, Hide, Refresh Quota, GPT Rain, Auto Open status and retry, and Quit, plus "抛物线" and "弹射" launch modes and separate "测试受击音" and "测试经验音" sound buttons. The test buttons do not change quota values, reset deadlines, or reset counts, and they do not inject a synthetic quota event. If a first-launch audio download failed, a test button can retry the download after connectivity returns; launching the app again also retries. Use these controls for safe manual sound checks without spending real quota or reset counts. The radial wheel is an app UI feature, separate from the Codex quota API.

The pet's status-bar menu has separate Show, Hide, and Quit actions. Manual Hide and Quit record the current Codex desktop PID set and timestamp in `~/Library/Application Support/CodexQuotaPet/visibility.json`. The watcher consults this file and suppresses automatic open requests for the same Codex process, including activation and Space-switch events; restarting the pet or watcher does not discard the choice. When a recorded PID set is available, only reliable evidence of a later Codex main-process launch clears the suppression. For an empty or malformed record, the watcher clears it only when it can identify the Codex main process and confirm its launch time is at least two seconds later than the hide record. New records use their recorded timestamp; older records use the file modification time. If the launch time is unknown, earlier, or too close to the record, keep the user's choice. Explicit Show clears the suppression and displays the pet. After Quit, the user can manually open `~/Library/Application Support/CodexQuotaPet/Codex Quota Pet.app` and choose Show from its status-bar menu; initially only the menu-bar icon may appear. Do not treat a hidden or quit pet as a failed watcher or reinstall the app to undo the user's choice. An internal shutdown of a temporary copy during installation is not a user Quit and must not create this suppression.

When asked to install or remove automatic startup on macOS, use the corresponding script under `native/macos/scripts/` only after reviewing its content. On Windows, use the documented application controls and current-user startup registration. Keep the user's artwork and source files in place. Never read or display Codex authentication files or tokens. If the local app-server returns no quota, show a concise unavailable state rather than a fabricated percentage.
